**폐기된 이전 결론 (스냅샷 시총 버킷팅):** 300M–1B가 −8~−14%로 최악, 100B+가 최고인 "완전 단조 사이즈 효과"로 보였다. **이는 대부분 look-ahead 편향이었다** — 이벤트 후 잘 오른 종목은 시총이 커져 큰 버킷으로(좋은 수익률을 들고), 떨어진 종목은 작은 버킷으로(나쁜 수익률을 들고) 분류되므로, 미래 시총과 사후 수익률이 **구성상** 상관된다. AAOI 검증(2026-02 이벤트가 $15B 스냅샷 때문에 10B-100B로 분류, 이벤트 당시엔 ~$6.8B)이 계기가 되어 발견. 재배치 규모: Case 1 769건(30%), Case 2 476건(28%).

이벤트 시점 기준의 실제 그림:
- **Case 1**: 사이즈 효과가 거의 평탄 (중간 버킷 ~+1.6%). 소형(300M–1B)이 오히려 +6.5%로 가장 좋으나 n=41로 얇다.
- **Case 2**: 완만한 기울기만 남음 (−3% → +3.4%). 소형 뉴스 갭 추격이 불리하다는 방향은 유지되나, 스냅샷 버킷팅이 보여준 −14% 같은 극단은 아니다.
- 잔여 한계: 발행주식수도 현재 값이므로 증자/자사주 변동은 미반영.

## 1. 목표

이벤트 이후 주가 흐름의 **raw 분포**를 통계로 남긴다. 두 이벤트 정의를 각각 측정한다.

- **Case 1 — 어닝**: 실적 발표 첫 반응일의 등락이 평소보다 컸을 때 이후 흐름
- **Case 2 — 비어닝 이슈**: 어닝이 아닌 이슈로 갭상승했을 때 이후 흐름

결론(평균)만이 아니라 **점도표로 raw 분포**를 볼 수 있어야 한다.

## 2. 용어

- **어닝 1day** — 실적에 처음 반응하는 거래일. `BMO`(pre) → 발표 당일, `AMC`(after) → 다음 거래일
- **어닝 2day** — 어닝 1day의 다음 거래일
- **이슈 1day / 2day** — Case 2에서 갭이 발생한 당일 / 그 다음 거래일
- **cc%** — 전일 종가 → 당일 종가 `(Close[t] − Close[t−1]) / Close[t−1] × 100`
- **gap%** — 전일 종가 → 당일 시가 `(Open[t] − Close[t−1]) / Close[t−1] × 100`
- **o2c%** — 당일 시가 → 당일 종가 `(Close[t] − Open[t]) / Open[t] × 100`
- **turnover** — `Close × Volume`

> 1day/2day 이동은 **캘린더가 아니라 거래일 인덱스** 기준이다. 금요일 AMC → 월요일, 휴장일 건너뜀이 자동 처리되어야 한다.

## 3. 이벤트 정의 (확정)

```
σ60      = 직전 60거래일 해당 지표의 표본표준편차 (과거 이벤트일 제외하지 않음)
z        = 지표값 / σ60                    # 평균 미차감, 레포 기존 관례

Case 1   (z_cc  >= 3.0  AND  cc  >= 4%)    # 어닝 1day close-to-close
   AND   (z_gap >= 3.0  AND  gap >= 4%)    # 어닝 1day 갭        ← 둘 다 충족

Case 2   z_gap >= 3.0  AND  gap >= 4%      # 갭상승, 어닝 1day/2day 제외
```

- 유효표본 60개 미만이면 `null` 처리 (기존 `newsVolatilityMetrics.ts` 규칙 유지)
- σ60 하한 0.3% 미만이면 제외 (분모 폭발 방지)
- **어닝 1day**: BMO → 당일, AMC → 익일. 세션 라벨이 없는 어닝은 **반응일 추론** — 당일 바가 위 조건을 전부 통과하면 BMO 간주, 아니면 익일 통과 시 AMC 간주 (`tod_inferred=True` 표기)
- **Case 2 어닝 제외**: 라벨 어닝은 1day·2day, 무라벨 어닝은 반응 가능 윈도우 **d~d+2** 전부 제외

- 이벤트 CSV 정렬: **event_date 내림차순 (최신 위)**
- 제목 컬럼은 **날짜 단위** 매칭이다 — 장 마감 후 발행된 PR(예: AMC 어닝 PR)도 그날 제목에 포함되므로, 당일 갭의 촉매가 아닌 제목이 섞일 수 있다. 갭의 촉매는 보통 전일 마감 후~당일 개장 전 PR이다.

- **CSV 선택 이유** — 이 작업은 일회성 통계 산출이고, 결과를 사람이 열어보고 엑셀·파이썬으로 재단하는 용도다. 신규 sqlite 테이블을 만들면 `app.db`(약 21GB) 스키마가 늘어나고 서버 코드·마이그레이션까지 건드려야 하는데, 재사용 계획이 없으면 과한 비용이다.
- **선행수익률은 종가만 저장하지 않고 등락률까지 같이 남긴다** — 재계산 없이 바로 점도표를 그릴 수 있게.
- **미완결 선행 구간은 빈칸(null)** 으로 두고 0으로 채우지 않는다.
- `ohlc_excluded_rows.csv` 는 정제로 버린 행을 남겨 "왜 이 이벤트가 빠졌나"를 추적할 수 있게 한다.

## 6. 실측 표본 (현재 데이터 기준)

> 아래는 **OHLC 정제 + B0 time_of_day 백필 적용 후** 최종 기준값이다.

### Case 1
| 단계 | 건수 |
|---|---|
| 어닝 BMO/AMC 중 OHLC 바 매칭 | 41,417 |
| turnover ≥ $100M, mcap ≥ $300M, σ60 확보 필터 | 통과 pool 약 16.9k |
| **확정 정의 (cc·gap 양쪽 z≥3, ≥4%)** | **2,575** |

- 1day o2c > 0 : **1,953** / o2c < 0 : **617**
- 752 종목, `2015-01-09` ~ `2026-05-01` — 2025-07 이후도 월 6~82건으로 정상 분포
- 선행수익률: +1M 2,536건 / +2M 2,521건 (54건은 OHLC 종료(2026-05-05)로 미완결)

**절대 하한 4%는 이 정의에서 거의 구속하지 않는다:**

| 변형 | 건수 |
|---|---|
| `z_cc ≥ 3` AND `z_gap ≥ 3`, 하한 없음 | 2,683 |
| + `cc ≥ 4%` 만 | 2,601 |
| + `gap ≥ 4%` 만 | 2,164 |
| **+ 둘 다 ≥ 4% (확정)** | **2,142** |

z 조건 두 개를 AND로 걸면 이미 중앙 gap이 7.5%라, 하한은 20%만 더 깎는다. 구속력은 `gap ≥ 4%` 쪽이 크다.

## 8. 스펙 변경으로 생긴 구조적 이슈

### C1. Case 1의 필터와 측정 대상이 부분적으로 겹친다
`cc ≈ gap + o2c` 이다. 즉 **cc 조건은 o2c 를 양수 쪽으로 끌어당긴다.** 실측:

| 이벤트 정의 | 건수 | o2c > 0 | o2c < 0 | 비율 |
|---|---|---|---|---|
| A. `z_cc ≥ 3` AND `cc ≥ 4%` 만 | 3,261 | 2,745 | 513 | 5.4 : 1 |
| B. `z_gap ≥ 3` AND `gap ≥ 4%` 만 | 3,263 | 1,773 | 1,484 | 1.2 : 1 |
| **C. A AND B (확정 정의)** | **2,142** | **1,626** | **513** | **3.2 : 1** |

gap 조건을 AND로 추가한 것이 편향을 **5.4:1 → 3.2:1 로 완화**했다. 다만 제거되지는 않는다.

주목할 점: **o2c < 0 버킷은 A와 C에서 똑같이 513건**이다. cc ≥ 4% 인데 o2c < 0 이려면 갭이 cc보다 더 커야 하므로, 그런 이벤트는 gap 조건을 자동으로 통과한다. 즉 **1-1-b(o2c < 0) 버킷은 정의상 전부 "크게 갭상승 후 되밀린" 케이스**이며, gap 조건 추가와 무관하게 513건으로 고정된다.

→ 결과 문서에 "o2c 양수 우위는 부분적으로 필터의 구조적 산물"임을 명시할 것.
→ **권고: 모든 이벤트 행에 `z_cc`, `cc`, `z_gap`, `gap` 을 전부 적재한다.** 비용이 없고, 나중에 A/B/C 어느 기준으로도 재단할 수 있다.

### C2. 전일 뉴스 포함 → **채택 (결정됨)**
T일 갭은 T−1 장마감 ~ T 개장 사이 뉴스가 만든다. 당일만 매칭하면 **T−1 애프터마켓 뉴스**라는 주된 촉매를 놓친다.

| 매칭 범위 | Case 2 이벤트 |
|---|---|
| 당일만 | 1,337 |
| **당일 + 전일 (채택)** | **2,193** (+64%) |
| 당일 + 전일 + 3일 전(주말 대응) | 2,300 |

부수 효과로 o2c 부호 균형도 좋아졌다 (703:640 → **1,152:1,035**).

**남은 정밀도 이슈:** 현재는 캘린더 날짜 단위로 매칭한다. 엄밀하게는 *"T−1 16:00 ET 이후 ~ T 09:30 ET 이전"* 이어야 하는데, `news_items.published_at` 포맷이 소스마다 섞여 있고(`2020-01-02 07:00:00`, `2026-02-05T01:00:00`, `...Z`) 타임존 표기가 일관되지 않다. 시각 단위 매칭을 하려면 **소스별 타임존 정규화가 선행**되어야 한다.
→ 우선 날짜 단위로 진행하고, `news_same_day` / `news_prev_day` 를 **별도 컬럼으로 분리 저장**해 나중에 재단 가능하게 한다.
→ 월요일 갭은 금요일 뉴스가 촉매인데 "전일"로는 못 잡는다. 3일 전까지 확장하면 +107건이므로, **직전 거래일 기준**으로 구현하는 편이 캘린더 −1일보다 정확하다.

## 9-1. Q2 — 하락 대칭 버킷 (결정: 미포함)

> **결정: 하락 버킷은 산출하지 않는다.** 아래는 결정 당시 검토했던 내용의 기록이다.


현재 확정된 Case 1 정의는 **상승 방향만** 잡는다.

```
z_cc ≥ +3  AND  cc ≥ +4%  AND  z_gap ≥ +3  AND  gap ≥ +4%
```

그런데 어닝은 **어닝 쇼크(급락)** 도 똑같이 만든다. 지금 정의는 그걸 전부 버린다. "대칭 버킷"은 부호만 뒤집은 짝을 말한다.

```
z_cc ≤ −3  AND  cc ≤ −4%  AND  z_gap ≤ −3  AND  gap ≤ −4%
```

**실측 규모 — 상승과 거의 대등하다:**

| | 상승 (현 정의) | 하락 (대칭) |
|---|---|---|
| 이벤트 | 2,163 | **1,978** |
| 중앙 cc | +12.15% | −11.50% |
| 중앙 gap | +9.10% | −8.87% |
| 중앙 1day o2c | +2.50% | −2.30% |
| o2c > 0 / < 0 | 1,647 / 513 | 520 / 1,453 |

**왜 필요한가 — 대조군이 없으면 결과를 해석할 수 없다.** 예컨대 "상승 이벤트 후 2day o2c 중앙값이 +0.5%"라는 결과가 나왔다고 하자. 이것이

- (a) 급등 이벤트에 **특유한** 현상인지,
- (b) 그냥 이 표본 전체의 일반적 드리프트인지

상승 버킷만으로는 구분할 수 없다. 하락 버킷이 대조군 역할을 해서, 두 쪽이 대칭이면 "방향과 무관한 드리프트", 비대칭이면 "방향 특유의 현상"으로 읽을 수 있다.

**비용은 사실상 0이다.** 같은 파이프라인에서 부등호만 뒤집으면 되고, raw CSV에 `direction` 컬럼(`up`/`down`) 하나만 추가하면 된다. 점도표도 같은 축에 두 색으로 겹쳐 그리면 비교가 바로 보인다.

→ 권고는 "함께 산출"이었으나 **사용자 결정으로 미포함 확정.** 파이프라인은 부등호만 뒤집으면 되는 구조로 짜서, 나중에 필요해지면 재실행만으로 하락 버킷을 뽑을 수 있게 한다.
